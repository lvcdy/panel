# 合并前安全评审清单

每个 PR 必须逐条确认；不适用的条目勾选并注明 N/A 理由。规则依据见
[ARCHITECTURE.md](ARCHITECTURE.md)，威胁模型见 [THREAT-MODEL.md](THREAT-MODEL.md)。

## 输入与输出

- [ ] 新增/修改的输入都经过**允许列表**校验（域名、IP、URL、类名、颜色、长度），
      没有用黑名单或正则「补丁式」拦截（E-01）。
- [ ] 新增输出都按上下文编码：HTML 用 `escapeHtml/escapeAttr`，DOM 文本用
      `textContent`，JSON 只回传白名单字段（E-02）。
- [ ] 没有把不可信数据拼进 `innerHTML`、`eval`、`new Function`、模板字符串后再
      二次解释执行。
- [ ] 错误响应不包含堆栈、内部路径或上游原始响应（G-02）。

## 信任边界与访问控制

- [ ] 新增跨信任边界调用（新 API、新第三方域名、新 localStorage 键）时，
      同步更新 [THREAT-MODEL.md](THREAT-MODEL.md)（A-01）。
- [ ] 新增 API 默认拒绝：方法白名单（GET/OPTIONS）、CORS 白名单、限速、
      输入校验四件套齐全（A-03、C-01）。
- [ ] 没有引入自研加密/协议/编码；需要密码学时使用标准库（D-01）。
- [ ] 没有硬编码新密钥；密钥通过环境变量/平台密钥管理注入（B-07、A-06）。
- [ ] 服务端没有新增写权限、持久存储或跨用户数据（A-07、D-08）。

## 数据与隐私

- [ ] 新增采集字段有明确用途；不采集与功能无关的个人数据（D-08）。
- [ ] 日志、埋点、错误上报中不含 IP、令牌、配置全文（B-04、H-01）。
- [ ] 浏览器存储/备份仍能在损坏时回退，且不覆盖用户原始数据（本仓库
      `panel-config-corrupt` 隔离机制）。

## 供应链与发布

- [ ] 未引入非官方 registry、预编译二进制或未声明的依赖；锁文件同步更新
      （F-08、J-03）。
- [ ] 依赖高危漏洞扫描通过（CI `dependency-audit`）。
- [ ] CI 安全任务（CodeQL、gitleaks、SBOM、签名、provenance）通过。
- [ ] 发布产物包含 `_headers` 安全头；CSP 变更评估了外部资源影响。

## 评审与记录

- [ ] 安全规则、`.github/`、`shared/api/` 的变更已由仓库所有者复核（I-04）。
- [ ] 新增安全相关测试用例（`tests/security.test.mjs`）并通过。
- [ ] 若本次变更有意接受残余风险，已在 PR 里书面登记风险与缓解计划。
